# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ABS_shim — a 100% serverless Cloudflare-native backend that mimics the Audiobookshelf (ABS) API so official and third-party ABS clients (web UI, ShelfPlayer, Pholia, mobile apps) can talk to it without modification. Driver: resilience while the user's self-hosted ABS Docker server is down. Stack: Cloudflare Workers (Hono on TypeScript), D1 (SQLite), Durable Objects, Workers Cache API, optional R2.

Storage backends are pluggable via `StorageAdapter`: filedn-public, S3-compat (R2/B2/AWS/Wasabi), WebDAV (NAS), pCloud OAuth. Multiple backends per library are supported.

## Architecture

**Worker entry**: `src/index.ts`. Outer `fetch()` strips the `/audiobookshelf/` prefix that the bundled Nuxt UI hardcodes, then routes via Hono. `app.notFound` branches on path: `/api/*` and `/auth/*` return JSON 404 (critical for strict clients), everything else falls through to `[assets]` SPA.

**Routes**: `/login`, `/api/authorize`, `/api/me`, `/api/items/*`, `/api/libraries/*`, `/api/admin/*`, `/api/session/*`, `/public/proxy/*`, `/admin` (UI), plus a Socket.io stub via `ListeningSessionDO`. Other DOs: `SignupRateLimitDO` (per-IP signup throttle), `ArchiveExtractDO` (zip extraction jobs). Auth middleware (`src/auth/middleware.ts`) accepts Bearer header, `?token=` query, or `accessToken` cookie. Cookie is refreshed on every `/login` AND `/api/authorize`.

**WebDAV, three ways it broke on one afternoon (2026-09-05).** All fixed, all worth knowing:
1. **Never probe through the proxy URL.** `resolveProbeUrl` used to return the signed `/public/proxy/...` URL, so the prober made the Worker fetch *its own hostname* — the edge answers that with **522**, while the identical Range request from a laptop returned 206 in 380 ms. It now returns the backend URL plus a `headers` field on `ResolvedUrl` (Basic auth), threaded through `probeM4b`/`probeMp3`/`probeOgg` and every internal range read. Miss one internal call and you get a **401 on a big file only**, because the first read succeeds and the follow-up read of a tail-placed moov is the one without the header. Client streaming still must use the proxy: a URL handed to a player can't carry a credential.
2. **A server URL with no scheme.** `dav.example.com/` was accepted by the attach form and made every `new URL(path, base)` throw `Invalid URL string`, reported as a scan error naming nothing. `normalizeWebdavBaseUrl` now prepends `https://` and validates, both at attach time and in the adapter constructor, so rows already stored that way are repaired on read.
3. **Depth: infinity refused** — see below.

**Folder picker** (`POST /api/admin/storage/browse`, owner-only): lists one level of an S3, WebDAV or pCloud backend from credentials passed in the body, before anything is saved, so attaching asks you to pick a folder instead of typing a path. S3 needs `S3Adapter.listDirectory` (a delimiter listing) because `listFolder` is prefix-recursive and file-only, which shows a bucket root as a flat object dump and no folders at all.

**WebDAV depth** (`src/storage/webdav.ts`): `walkAudiobookFiles` tries one `Depth: infinity` PROPFIND and falls back to a bounded breadth-first walk of `Depth: 1` requests when the server refuses it. RFC 4918 lets a server decline (403 + `propfind-finite-depth`), and Joseph's NAS answers `400 Invalid depth: only 0 and 1 are allowed`, which failed the entire scan before 2026-09-05. Keep the infinity attempt: it is one request instead of one per folder. The fallback stops at 400 folders / 8 levels so a folder pointed at a whole NAS share can't burn the Worker's subrequest budget.

**Storage adapters** (`src/storage/`): `adapter.ts` defines the interface — `resolveUrl`, `resolveProbeUrl`, `listFolder`, optional `walkAudiobookFiles`. `factory.ts` builds an adapter from a `library_folders` row. The adapter for streaming is invoked from `src/storage/resolve.ts` — it falls back to `audio_files.filedn_url` when `rel_path` is null (preserves backward compatibility with the original seed).

For backends that can't 302 directly (WebDAV), `proxy-url.ts` mints HMAC-signed self-Worker URLs and `index.ts` has a `/public/proxy/:folderId/*` route that validates the signature and proxies bytes. Streaming through a Worker is fine — once you `return` a `Response` with a `ReadableStream` body, CF's edge runtime pipes bytes without using your Worker's CPU budget.

**Scanner** (`src/scanner/scan.ts`): `runScan()` enumerates folders for a library, calls `adapter.walkAudiobookFiles`, probes each new m4b via `src/prober/m4b.ts`, and inserts library_items + book_metadata + audio_files + chapters in one D1 batch. Public-URL adapter throws `ListingNotSupportedError` (filedn has no listing API). `addBookByPath()` is the per-file alternative.

**Prober** (`src/prober/m4b.ts`): pure-JS MP4 atom walker, reads moov via Range requests, extracts mvhd duration, udta/meta/ilst tags (incl. `----:<mean>:<name>` custom tags), covr cover. No FFmpeg.

**mp3 chapters**: `src/prober/mp3.ts` reads ID3v2 `CHAP` frames (how single-file mp3 audiobooks carry chapters); `mp3Chapters()` in the scanner merges them across a folder of files (a file without CHAP is one chapter). `reprobeItem` dispatches mp3 items to `reprobeMp3Item`; "Re-probe books missing chapters" in /admin includes 1-chapter books for exactly this case.

**Recently Added** (`buildPersonalizedShelves`): newest-first, but a run of same-series books added within 30 min is shown Book 1 first.

**Series** (`src/lib/series.ts`): `deriveSeries()` fills `book_metadata.series_name/series_sequence` at scan time and on reprobe (only when NULL). Tags first (`----:com.apple.iTunes:SERIES`/`SERIES-PART`, `©mvn`/`©mvi`, `tvsh`/`tves`, `©grp`), then a folder/title heuristic for AudioBookBay-style "Title Series, Book N - Author" folder names. Minified `seriesName` is emitted as `Series #N` like real ABS; Pholia parses that for its "Book N" badge. Metadata lives only in D1 — the files on pCloud are never rewritten.

**Admin UI** (`src/lib/admin-html.ts`): single self-contained HTML+JS embedded in the Worker (a `String.raw` template — regex escapes are verbatim), served at `/admin`. Cookie-authed with inline login form. Renders all library_folders per library (multi-backend), with attach buttons for S3/WebDAV/pCloud, chunked browser upload (zip/rar extracted client-side via libarchive.js), fetch-from-URL, and the AudioBookBay → Real-Debrid panel. Before deploying UI changes: extract the `<script>` and run `node --check` on it — there's no other syntax check.

**Fetch-from-URL + zip extraction** (pcloud_oauth folders only). `POST /api/admin/storage/folder/:id/fetch-url/start` asks pCloud to pull a direct URL itself (`downloadfileasync`); the browser polls `/progress`, which `stat`s the target and compares to the source's Content-Length (pCloud's `uploadprogress` never reports these jobs), then `/finish` registers via `addBookByPath`. Zips are handed to `ArchiveExtractDO` (`src/do/archive-extract.ts`, reader in `src/archive/zip.ts`): it Range-reads the central directory, streams each audio entry through `DecompressionStream('deflate-raw')` into pCloud's chunked upload, one alarm per entry. pCloud's own `extractarchive` API is broken (3006 on everything) — don't retry it. rar is not extracted server-side.

**Stopping duplicates before they reach pCloud (2026-09-06).** The real cause was a grab that missed tracks: the fix is to run it again from the "On Real-Debrid" panel, but the second pass recomputed its destination and filed the stragglers as a *new* book. `abb_grabs` (migration 0013) remembers which folder each info hash landed in, `fetch-url/start` records it (`sourceHash`/`sourceTitle`), and `GET /api/admin/abb/grabs?hash=&title=&folderName=` is asked before any torrent is added:
- a known hash → its recorded folder is reused, and the row says "topping up", so the missing tracks complete the book;
- otherwise, library items that look like the same book (same folder name, or overlapping title words) come back as `matches` and both UIs confirm before downloading a second copy.

`looksLikeSameBook` compares the listing title against the book's title words **with the author's words removed**: an ABB listing reads "Author - Title - format", so counting author words made every book by that author a match (the first cut flagged all five Dennis E. Taylor titles for a Flybot grab).

**Duplicate books, and why the scanner can't prevent them.** Registration is idempotent per `(folder_id, rel_path)` — migration 0006 — so grabbing one release twice into *different* folders gives two library items, correctly, because at that level they are two different books on disk. `GET /api/admin/libraries/:id/duplicates` groups items by title+author, flags `acrossBackends` (one copy per backend is usually deliberate — Joseph keeps Flybot on both — while two copies on ONE backend is the accident) and reports every group larger than one, with each copy's path, file count, length and size, since the copies are often *partial* (a resumed grab splits the parts) and the longest one is the keeper. /admin's "Find duplicates" button per library renders it.

**Real-Debrid renames a torrent to its selected file.** Once one file is selected, `filename` on the torrent is that file's name, and the torrent's own name only survives in `original_filename` (surfaced as `originalFilename` on both torrent routes since 2026-09-06). Anything that becomes a *folder* must use the original: resuming a multi-file mp3 grab from the "On Real-Debrid" panel used `filename`, so the parts landed in directories called `Dawnlands-Part04.mp3` and `Dawnlands-Part17.mp3` — three copies of one book in the library, each with a different subset of chapters.

**AudioBookBay → Real-Debrid** (`src/lib/abb.ts`, `src/lib/realdebrid.ts`, `src/routes/abb.ts` at `/api/admin/abb`). Credentials are per tenant in `tenant_settings` (migration 0005) — since 2026-09-02 only the Real-Debrid token is asked for in /admin (the ABB info hash is public on every detail page, so a member login adds nothing; the route still accepts the old fields), sealed with AES-GCM via the `SETTINGS_KEY` secret (`src/lib/secret-box.ts`). The browser drives the flow: (`details?url=` on tap shows the listing's blurb/author/narrator) `resolve` (`{url}` or a pasted `{magnet}`) → `torrents {inspect:true}` (add, list files, delete) → file-picker modal when >1 candidate → `torrents {fileId}` one torrent per chosen file (RD packs multi-file selections into a rar) → poll `torrents/:id` → `fetch-url/*` per direct link. Since 2026-08-24 the flow NEVER auto-deletes RD torrents (success, cancel, error and stall paths all leave them; RD expires them itself) — only the panel's Delete button and deselecting files in the picker delete, because auto-delete on a failed fetch destroyed the only retry path. Destination paths come from `abbPlanDest` (same code in both UIs): the dirs all chosen files share collapse to the deepest one, sub-folders below are kept (one book per folder), and m4b siblings in one dir each get their own folder — don't flatten, the scanner would merge a 4-book pack into one broken item. Grabs have a Cancel button and give up on a torrent with no progress for 20 min (both leave the torrent on RD to resume later). `DELETE /api/admin/items/:id?deleteFiles=1` removes the audio files from pCloud (then the empty folder, then D1) — used by /admin "Delete + files" and Pholia's long-press; without the flag it's D1-only as before. Because the flow is browser-driven, a closed tab orphans torrents on RD; `GET /api/admin/abb/torrents` lists them and both UIs have an "On Real-Debrid" panel with Finish / Watch / Delete that feeds `abbTrackTorrents` (the shared poll→fetch→scan tail of a grab) using `torrents/:id`'s `selectedFiles` to recompute the destination. `fetch-url/start` treats "same path AND same byte size as the source" as already landed (no hash is available) and the client skips to `/finish`; a size mismatch is a 409. ABB search queries must be lower-case (capitals → 301 to the homepage). `fetch-url/finish` only registers single m4b/m4a/aac files, so when any file of a grab did *not* register, both UIs `POST /api/admin/libraries/:id/scan` afterwards — that's what picks up mp3 (multi-file) releases; don't drop it, and don't run it unconditionally (a scan racing another grab's `/finish` is how duplicates happened). Pholia's "Add" screen (header ABB icon) calls these same routes (plus the scan route) — keep the two repos in sync when changing them.

**AudioBookBay catalogue** (`src/lib/abb-catalog.ts`, migration 0007, cron in `wrangler.toml` `[triggers]` → `scheduled()` in `src/index.ts`). A local copy of ABB's listings in D1 (`abb_posts` + `abb_post_cats` + FTS5 `abb_posts_fts` kept in sync by triggers + `abb_crawl` state). One row per ABB *post URL*, never per title (re-posts like `title-author-2` are separate torrents with their own hash). Every ABB listing (home + ~62 category/language pages) is capped at 500 pages of 9 posts — page 501+ silently repeat page 500 — so the catalogue is "what listings show today + everything from now on + whatever live searches turn up" (live search extras are upserted in the background); nothing older can be enumerated. **ABB firewalls IPs that fetch in bursts** (≈50 pages in 3 min got this Mac dropped at TCP level on 2026-09-02, while a VPS still got 200), and the crawler shares Cloudflare egress with the shim's own live search, so the tick is deliberately timid: every 2 min, `stats.budget` fetches (default 6, adjustable in /admin), 4 s between fetches, and three timeouts/403/429/503 in one tick trigger an exponential backoff (30 min → 24 h) plus a Pushover push (two signals / 2 h was a false alarm on 2026-09-02: a slow patch after 168 clean ticks). Tick order: home page check every 15 min (stop at the first page with nothing new), then the remaining budget split between advancing the first unfinished listing's cursor and fetching detail pages (info hash + author/narrators/blurb) newest-first. A 200 listing page that parses to 0 posts is counted as `zeroParsePages` (markup drift alarm shown in /admin). Routes: `GET /api/admin/abb/catalog/{status,categories,browse}`, `POST …/catalog/run` (one tick now), `POST …/catalog/control` (owner only: pause/resume/retry-errors/restart-backfill/reset-report/set-budget/clear-backoff/send-report). `search` merges catalogue hits (FTS-ranked) with live results and tolerates a live failure (`liveError`, `?mode=cache|live|both`); `resolve` and `details` answer from the catalogue when the hash/details are cached and record live results into it. The 14-day check-in Pushover (`REPORT_AFTER_MS`, first started 2026-09-02) fires from whichever tick first runs past the deadline. Both UIs have a browse-by-category row (Pholia: `abbLoadFacets`/`abbBrowse` in app.js) that renders through the same result renderer as search.

**Catalogue crawl fanned out to wharf nodes (2026-09-03).** `wharf-project/{abbcrawl,abbcovers}/` — two on-disk wharf projects (one `[[services]]` each, no handlers), deployed by `wharf-project/deploy.sh <project> <user@host>`. **Two projects, not one, because wharfd runs every service in ONE systemd cgroup with a per-box `MemoryMax`**: the Pillow cover runner alongside the crawler OOM-killed wharfd on stereo-nz 75 times in an hour on 2026-09-03 (cap 128 MB, a leftover from the 450 MB VPS profile — the box has 7.3 GB), restarting netprobe and cfpbx-stereo's ESL forwarder every time. Check `systemctl show wharfd -p MemoryMax -p MemoryCurrent` before adding a service to a node. Both stereo boxes were raised to 512 MB on 2026-09-03 via `/etc/systemd/system/wharfd.service.d/20-memory.conf` (a drop-in, so a wharf update keeps it); the PBX VPS keeps 128 MB because it really has 451 MB of RAM. Job handlers are capped separately by `systemd-run --scope`, so only `[[services]]` spend this budget. As of 2026-09-05 **both** stereo-nz and wharf-syd-1 run `abbcrawl` + `abbcovers` (cover shards 0 and 1 of 2 — one runner stopped keeping up once the listing backfill started adding ~30 posts a minute); **stereo-au runs neither** — it can't reach ABB at all, and its covers capacity isn't needed. ABB is reachable from the other two, but **not from stereo-au** — not geography: stereo-au shares Joseph's home WAN IP, which ABB firewalled during the 2026-09-02 burst and still drops SYNs from a day later. Diagnosed 2026-09-03: DNS is identical from the home resolver, 1.1.1.1 and 8.8.8.8 (so a different DNS changes nothing), Vultr *Sydney* reaches ABB in 2.3 s, and the `audiobookbay.li` mirror on a different IP completes TLS from the home IP — only the pair 49.179.117.247 → 176.97.124.219 is dropped. Test a new node with exactly one curl, never a loop. `abb-detail-crawler.py` claims batches over `POST /api/admin/abb/catalog/details/claim` (owner-only), fetches each detail page one per `PACE_SECONDS` (8 → ~7/min per node) and posts the raw HTML to `…/details/submit`, which parses it Worker-side — no ABB markup knowledge on any node, so a parser fix still ships with the shim. Claims are **leases** (migration 0010 `detail_claim_by`/`detail_claim_until`, 10 min): the `UPDATE … RETURNING` is one statement so two nodes can't take the same row, a dead node's rows lapse back into the pool, and `detailPass` (the cron) skips leased rows. Nodes work the **oldest** pending posts, the cron the newest, so they only meet when the backfill is done. Three consecutive failures → the node releases its batch and sleeps 30 min, doubling to 6 h. Per-node counters live in `abb_crawl` rows keyed `node:<name>` (one row per node — a shared blob would lose concurrent updates) and show in /admin's catalogue card. The sibling `abbcovers` project runs the **cover** resizer that used to live on Joseph's laptop: `scripts/abb-covers.py` (copied to the node by `deploy.sh`, never forked) with `--shard/--shards` (also `ABS_SHIM_SHARD/SHARDS`), which `covers/pending` honours as `id % shards` — a fixed partition, no lease, because a duplicated PUT only wastes a download.

**ABB search language filter (2026-09-03).** `/api/admin/abb/search?lang=English` filters the catalogue half in SQL (`catalogSearch`, `COLLATE NOCASE`) and the live half on the language ABB itself prints — their search has no language parameter. Live hits are still upserted into the catalogue in full; only the response is filtered, and `filteredOut` says how many were hidden. **Both UIs default the picker to English** (12,065 of 12,370 catalogued posts) and remember a manual choice for the session; Pholia uses ONE picker for search and browse (`_abbLang()`), because a phone row can't carry two.

**Cover runner failure classes (2026-09-03).** `scripts/abb-covers.py`'s three steps report three different failures, and this matters: `urllib.error.HTTPError` and Pillow's `UnidentifiedImageError` are both `OSError` subclasses, so a single `except (URLError, TimeoutError, OSError)` filed dead links and corrupt JPEGs as "our network is flaky, leave it pending" — they came back every pass forever until ~1 image in 60 was getting through and the backlog climbed with new posts. Rule: **the host answering (any HTTP status) or the bytes not decoding is permanent → record it via `…/covers/:id/error`; no answer at all → leave pending.** Batches log their skip/mark reasons. A name that doesn't resolve is retried 3× (1 s/3 s) and an all-skipped batch is retried once after 20 s before the pass gives up: the wharf nodes resolve through **Tailscale MagicDNS** (`nameserver 100.100.100.100`), whose upstream returns SERVFAIL in bursts under a cover pass's lookup rate — on 2026-09-05 at 01:48 tailscaled logged `forward: sendUDP: response code indicating server failure: 2` at the exact second a batch skipped 60 of 60, and aborting there cost a 15-minute sleep for a blip that cleared in seconds. `POST …/catalog/control {action:'retry-cover-errors'}` (and the /admin button) clears `cover_error` when a host recovers, and every control action now returns a `message` saying what it did.

**One empty listing page is not the end (2026-09-03).** ABB ends a listing with a 404 but sometimes serves an empty HTTP 200. Treating the first one as final retired listings that plainly weren't finished — "Action" at page 4, "Adventure" at 11, five in all sitting `done` with `error: 'parser found 0 posts'`. `backfillPass` now needs `emptyStreak >= 2` before marking a listing done (a single empty leaves the cursor and retries next tick), and the five were reset in prod with `emptyStreak: 1`.

**Catalogue dashboard (2026-09-03).** /admin's catalogue panel polls `/catalog/status` every 10 s while it's open and the tab is visible (`abbCatalogPolling`), and leads with four tiles — posts cached / with a magnet / awaiting details / covers cached — each showing movement since the panel was opened with *direction-aware* colour (`catTile({down:true})`: falling is green for the backlog). `catalogStatus` now also returns `covers` and a server `now` so rates aren't computed against a skewed browser clock. Below them one row per worker (cron + each wharf node) with a liveness dot. A listing that finished with an empty HTTP 200 sets `ended`, not `error`, so it no longer shows a ⚠, and `fetchListingPage` only counts `zeroParsePages` where an empty page can't mean end-of-listing (page 1 and the fresh pass) — four of the four "markup may have changed" alarms were listings that had merely finished.

**ABB fetch retries.** `abbFetch` (the interactive paths: search, resolve, details) retries 5xx and network errors 3× with 1 s/3 s backoff. ABB sits behind Cloudflare and a transient **522** (edge can't reach their origin) used to kill a whole grab mid-tap from Pholia. 4xx are never retried — notably 404, and the 301-to-homepage ABB serves for a query with a capital letter. The crawler still calls `abbFetchRaw` directly: it has its own budget, 4 s spacing and backoff, and must not gain a hidden 3× multiplier.

**Catalogue covers + in-library badge (2026-09-02).** Workers can't resize images and Cloudflare transformations would cost ~$20 for the catalogue, so `scripts/abb-covers.py` (Pillow) runs off-Worker — on a Mac, and since 2026-09-03 as the `abb-covers` service on both wharf nodes (see the crawl fan-out below): `GET /api/admin/abb/catalog/covers/pending` → download → fit in 500 px webp → `PUT …/covers/:id` (R2 `abbcovers/<id>.webp`, migration 0008 `cover_r2`/`cover_error`) → served at `/public/abb-cover/<id>.webp` (edge-cached, immutable). `withCoverUrls` swaps the hosted webp into `cover` and keeps the source in `coverOrig` (both UIs open it in a lightbox on cover tap). `--sample N --quality 30,45,60` writes local files for eyeballing; `--upload` is re-runnable (pending only; failures recorded via `…/covers/:id/error`). `markInLibrary` flags results whose grab folder name (`folderNameFromTitle`) matches a library item's top folder → "✓ In library" / "Grab again"; `fetch-url/finish` and `upload/save` return `alreadyInLibrary` so a re-grab reads as such.

**Opus/Vorbis** (`src/prober/ogg.ts`): OpusHead/OpusTags (or Vorbis headers) from a head Range read, duration from the last granule (48 kHz for Opus, minus pre-skip), CHAPTERnnn/CHAPTERnnnNAME chapters, METADATA_BLOCK_PICTURE cover, narrator from NARRATOR/PERFORMER/COMPOSER (ffmpeg maps ©wrt to COMPOSER). Scanner, `addBookByPath`, `fetch-url/finish`, reprobe and the cover fallback all dispatch on `.opus|.ogg`; rows use mime `audio/ogg; codecs=opus`, format `ogg`, no moov cache.

**Passkeys** (`src/routes/passkeys.ts` at `/api/auth/passkey`, primitives in `src/auth/webauthn.ts`, migration 0009). A TypeScript port of Pholia's WebAuthn functions (ES256 only, pure Web Crypto + a minimal CBOR decoder — npm WebAuthn libs need Node Buffer). Register is auth-only (a passkey is a second door into an existing account, never account creation); sign-in is discoverable (no username) and issues the same access/refresh tokens + `accessToken` cookie as `/login`. Hardened beyond Pholia's version: the RP ID comes from the request URL's hostname (never the Origin header) and every authData's rpIdHash is checked. The /admin login card shows "Sign in with passkey" when the browser has a platform authenticator; a Passkeys card lists/adds/removes the signed-in user's passkeys. Verified with a synthetic ceremony (real P-256 signatures, tampered signature rejected) — see the 2026-09-02 session.

**Audible import** (`src/routes/audible.ts` at `/api/admin/audible`, client `src/lib/wharf.ts`, wharf project in `wharf-project/audible/`). The work runs on wharf: the shim submits jobs to project id `audible` through the **wharf-router** (service binding `WHARF_ROUTER` + secret `ROUTER_TOKEN`, from `wharf-installs/router/secrets.yaml` via sops); the router forwards to whichever island hosts the project — **stereo-au** today (FCOS, Tailscale 100.121.86.110, `ssh core@…` + sudo; project at `/srv/wharf/projects/audible` with its own venv (audible-cli), static `bin/ffmpeg` + `bin/rclone` (the capability installer measures the immutable root fs and refuses), `data/rclone.conf` (pCloud remote copied from syd), `data/cli/<account>.json` auth files). Moving it = router route change (`ROUTES` in the wharf repo's `router/wrangler.toml`, `"audible":["stereo-au"]`) + the island's `router-*` cred listing the project; the shim doesn't change. Handlers: `auth_start` (Amazon sign-in URL built with the `audible` library's PKCE flow; the user signs in in their own browser and pastes the maplanding error-page URL) → `auth_finish` (register device, save auth file, regenerate audible-cli `config.toml`), `accounts`, `remove_account`, `library` (paged `1.0/library`, cached in `data/library`), `sync` (audible-cli `download --aax-fallback --cover --chapter` → ffmpeg decrypt with the voucher key/iv or activation bytes, remux `-c copy` to fast-start m4b with an ffmetadata file for tags + chapters (lands as chpl, which our prober reads) and the cover attached → **stage in R2** (`rclone copyto r2:abs-shim-audible-staging/…`, then `rclone link`) → pCloud `downloadfileasync` from the signed URL, `stat`-polled to size, R2 object deleted → `pcloud:<library rootPath>/Audible/<account>/<Title - Author>/<Title>.m4b` → `data/synced/<account>.json`). Direct rclone→pCloud from stereo-au ran at 37 KB/s (2026-09-03), hence the R2 hop; the `r2` remote's account-wide S3 keys sit in the project's `data/rclone.conf`. `sync.yaml` has `max_memory_mb: 4096` (1 GB was OOM-killed by the download's page cache) and `project.toml` `[slots] total = 3` (1 slot queued every lookup behind a running sync). Audible titles with `is_consumable_offline=false` (Originals typed "Performance", episodic "Show", Plus catalogue) can't be downloaded at all; the UI greys them out. wharf runs an approved handler from a **copy** in `state/registered/`, so scripts locate `handlers/_lib` from the cwd (project dir), and `ensure_venv()` re-execs into the venv by comparing `sys.prefix` (the venv python is a symlink to the system one). Handler stdout must be exactly one JSON object (the job result); progress goes to stderr (job log, tailed by the UI). Re-registering after a script change: `wharf handler register audible <manifest.yaml>` + `approve` (hash-pinned). Routes are owner-only and 503 without the binding; the /admin Audible card hides itself on 403/503. After a sync succeeds the UI scans the target library once (`jobs/:id/scanned`).

**Pholia is not bundled here (but does call shim-only routes).** Pholia (github.com/jowtron/pholia) has its own Cloudflare Pages deploy at pholia.jderrick.app (Pages project `pholia` on the Josephderrickrepairs account, alias pholia-3fd.pages.dev; the old pholia.pages.dev is a stale project on another account — ignore it) with its own D1 database (`pholia-accounts`) backing a passkey-protected saved-server vault. WebAuthn passkeys are bound to RP ID = the browser's hostname, so re-hosting Pholia under `/pholia/` on the shim would break every existing passkey (users would have to re-register on the shim hostname). The /admin UI's "Open Pholia" mints a fresh access token via `/api/authorize` and opens pholia.jderrick.app with `#connect=<base64url {s,u,t}>` in the fragment (never sent to a server, stripped by Pholia on arrival) — Pholia adopts it as its ABS session, so a member never types a server address. **iOS home-screen apps have their own storage partition**, so that session does not survive "Add to Home Screen"; Pholia handles it (2026-09-05) by baking the server + username into the manifest's `start_url` and by offering a passkey right after the hand-off whose vault entry stores the *token* (rotated via `/api/authorize` while the app is in use) — see the "Persistent Login" section of Pholia's CLAUDE.md before changing the hand-off payload or token lifetime (`ACCESS_TTL_SECONDS`, 30 days: Pholia's rotation window assumes ≥ 20 days). Don't try to bundle Pholia under a sub-path here. Pholia (checkout `/Users/joseph/Claude_Code/pholia/pholia`, deploys on push via GitHub Actions) detects the shim by probing `GET /api/admin/abb/settings` and shows its "Add" screen (an ABB-logo icon in the header beside search) only on a shim with a Real-Debrid token configured.

## Roles inside a tenant (2026-09-05)

Until 2026-09-05 every `/api/admin` route was open to any active member, so a member could disconnect the owner's pCloud or delete the library. Three tiers now, enforced in `src/auth/middleware.ts` and mirrored (hidden buttons only) in /admin and Pholia:

- **anyone in the tenant**: read status, scan, re-probe, warm covers, see the member roster, ABB catalogue search/browse. Scans stay open on purpose — a member who adds a book and doesn't see it needs "Scan now".
- **`requireCanAdd`** (owner, or a member when the tenant setting `members_can_add` is on — the checkbox in /admin's Library members card, `POST /api/admin/tenant/settings`): upload, fetch-from-URL, zip extract, add-by-path, ABB `resolve` + all `torrents` routes, and the whole Audible importer. A member sees only **their own** Real-Debrid torrents (`rd_torrents`, migration 0011, recorded at add time, pruned against RD's list because RD expires torrents itself; other people's ids answer 404) and only the Audible accounts and sync jobs they created (`tenant_settings` `audible_account_owners` + `userId` on job records). The owner sees everything.
- **`requireTenantOwner`**: connect/attach/remove storage, `DELETE /api/admin/items/:id` (with or without `deleteFiles`), invites, ABB settings + crawler control. `storage/status` also omits `profiles` for members.

`GET /api/admin/abb/settings` is the capability probe both UIs use: `canGrab`, `canDelete`, `membersCanAdd` (Pholia treats missing flags as allowed for older shims). When adding an admin route, pick a tier explicitly — the default is "anyone in the tenant".

## Strict-client compatibility (ShelfPlayer)

ShelfPlayer uses strict Swift Codable — one field type mismatch fails the entire response, and array-decode failures wipe whole shelves. Lessons learned and locked into the code:

- `publishedYear` is a STRING in the wire format, not a number (despite being stored as INTEGER in D1). Don't change `String(m.publish_year)` in `src/lib/abs-shapes.ts`.
- `media.tracks` is required for playback — built from audioFiles with cumulative `startOffset` in `buildTracks()`.
- `/api/*` paths MUST return JSON 404, never the SPA index.html — strict clients parse HTML 200 as garbage and go offline.
- See `~/.claude/projects/-Users-joseph-Claude-Code-ABS-shim/memory/reference_shelfplayer_quirks.md` for the full debugging methodology.
- Session sync bodies use `timeListened` (real ABS spelling; Pholia and ShelfPlayer send it) — `listenedDelta()` in `src/index.ts` also accepts the old `timeListening`. It's a per-sync delta, so it's ADDED to `listening_sessions.time_listening_seconds`.
- CORS `allowHeaders` must keep `X-Playback-Session-Id` (plus `If-Range`, `Accept`): Pholia's service worker re-issues iOS media requests as CORS fetches when it serves a partially cached book, and iOS adds that header to every media request. Without it the preflight fails and playback dies at the cache edge. iOS also requires every response in one media load to have the same CORS status, so the shim's file route must behave identically for CORS and no-cors requests (it does — don't add Origin-dependent branches).

When adding a new client integration: open `wrangler tail --format pretty` and use `gh api repos/<owner>/<repo>/contents/<path> --jq '.content' | base64 -d` to read Swift Codable structs. Diff the strict types against `src/lib/abs-shapes.ts` output.

## Search, and two things that had quietly never worked (2026-09-06)

- **`GET /api/libraries/:id/search`** returned an empty result set for every query — a stub nobody had filled in, so Pholia's search box looked broken rather than unimplemented. It now does a case-insensitive substring match over title, subtitle, author, narrator and series, returning ABS's `{book:[{libraryItem, matchKey, matchText}], authors, series, narrators}` shape with title matches ranked first. **D1's `bind()` is positional only** — numbered `?1` placeholders fail with "Wrong number of parameter bindings", so the pattern is bound once per placeholder. `%` and `_` in the query are escaped, or a search for "50%" would match everything.
- **The `accessToken` cookie was `Max-Age=3600` while the token inside it lasted 30 days**, so the bundled web UI and /admin forgot you after an hour while Pholia, holding the same token in localStorage, stayed signed in for a month. `src/auth/cookie.ts` now mints it with the token's own TTL, plus `Secure` on https. Shortening it never bought anything: the token is equally valid either way.
- **Detaching a storage backend takes its books with it** when called with `?removeItems=1`, which is what /admin now does after confirming. Nothing is deleted from the storage itself. Note `library_items.folder_id` is `ON DELETE CASCADE`, so deleting the folder row removes its books whether or not you ask — the 409 guard for the un-flagged call is the only thing standing between a mis-click and a wiped shelf, and it counts by `folder_id` alone (adding `tenant_id` to that count would let a row with drifted tenancy slip past it, which is exactly what happened to the local seed while testing).

## Which backend is a book on? (2026-09-05)

`src/lib/storage-label.ts` is the single answer: `storageLabel(folder)` → `{provider, name, detail}` ('pCloud' + rootPath, a bucket + prefix, a WebDAV hostname). It feeds the scan report, /admin's folder rows, and a **non-ABS `storage` field on every entry in `media.audioFiles`** (strict clients ignore unknown keys), which is what Pholia shows beside the codec on the book page and in the flip-side file info panel. Nothing in either UI could answer the question before, and the same title can legitimately exist on two backends as two separate `library_items` rows with separate progress — scanning finds each independently and neither knows about the other. There is no de-duplication; removing one is a manual delete.

## Scan reports say which backend (2026-09-05)

`ScanReport.folders` carries one `ScanFolderReport` per storage backend — provider, a human label built from its config, added/skipped/error counts and up to 50 added paths — and every error row carries `folderId` + `backend`. A library can have several folders, so "added 3, 1 error" said nothing about which NAS or bucket was involved. `/admin`'s scan output and the folder rows both print it; `storage/status` also returns per-folder book counts.

## D1 cost: index what you filter on (2026-09-05)

D1 bills rows *read*, and a query with no usable index reads the whole table every call. `DELETE FROM abb_post_cats WHERE post_id = ?` — run once per post on every listing pass to rewrite its categories — had no index leading with `post_id` (the primary key is `(cat, post_id)`), so each of those ~59k calls scanned all ~119k rows: **3.8 billion rows read, about 99% of this database's entire read volume**, to touch two or three rows. Migration 0012 adds `abb_post_cats(post_id)`. Check `EXPLAIN QUERY PLAN` for any statement that filters a big table on something other than its leading key column; "SCAN" in the output is the alarm.

The other repeat offender is a whole-table aggregate behind a polling UI: /admin's catalogue tiles poll every 10 s and each poll ran `SELECT COUNT(*), SUM(…) FROM abb_posts` twice, 23k rows a time. `catalogCounts`, `coverStats` and `catalogFacets` now go through `cachedAggregate()` in `src/lib/abb-catalog.ts`, which keeps the answer in an `abb_crawl` row (one indexed read) for 60 s — 15 min for facets — and `catalogControl` calls `bustCatalogCaches()` so a button press still shows its effect at once. Cache any new dashboard aggregate the same way.

## Schema (D1)

Migrations in `migrations/`. Initial schema (0001) plus storage additions (0002): library_folders gained `provider`, `config_json`, `profile_id`; audio_files gained `rel_path`, `provider_file_id`; new tables `oauth_profiles`, `oauth_state`. 0003 moov cache, 0004 multi-tenancy (`tenants`, `tenant_members`, `invites`, `tenant_id` columns), 0005 `tenant_settings` (per-tenant key/value; `server_settings` stays instance-wide), 0006 UNIQUE `library_items(folder_id, rel_path)` — concurrent registrations of one path used to double-insert; scanner/`addBookByPath` treat the violation as "already in library". IDs are TEXT (UUIDs or `li_…`/`mp_…`). Timestamps INTEGER ms-epoch. JSON-shaped fields are TEXT, accessed via `JSON.parse`.

`audio_files.filedn_url` is legacy/back-compat for the original seed; new rows insert `rel_path` instead, and `resolveStreamUrl` picks the right path.

## Production state

- Deployed to a Cloudflare Worker (URL configured in `wrangler.toml`).
- D1 `abs-shim-db` seeded via `npm run db:seed:local`. Real folders are added at runtime through the `/admin` UI rather than committed to the seed file.

Optional: `PCLOUD_CLIENT_ID`, `PCLOUD_CLIENT_SECRET` (only if using pCloud OAuth). - Bootstrap: hit `/init` once to create the root user. Verified working clients: bundled ABS web UI, Pholia, ShelfPlayer.

## Conventions

- Hono routes are thin; logic lives in `src/lib/`, `src/db/`, `src/storage/`, `src/scanner/`.
- Don't introduce new runtime dependencies casually — Workers Free has size constraints; current dep list is just `hono`.
- Don't add `nodejs_compat` — pure-JS only on the Worker side.
- TypeScript is strict (`exactOptionalPropertyTypes`); guard against undefined explicitly when building objects with optional fields.
- Comments explain the *why*, not the what. Many comments in this codebase reference past bugs ("Don't change this — without it ShelfPlayer goes offline"), which are load-bearing.
